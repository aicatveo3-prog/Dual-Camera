# 앞뒤 동시 카메라 (Dual Camera)

한 기기에서 전면·후면 카메라를 켜고 두 화면을 함께 보여주는 보기 전용 웹 페이지입니다.
설치나 빌드 없이 브라우저에서 바로 실행되며, 모든 코드가 `index.html` 하나에 들어 있습니다.

**▶ [바로 열기](https://aicatveo3-prog.github.io/Dual-Camera/)**

> 카메라 API는 **HTTPS에서만** 동작합니다. 위 GitHub Pages 링크는 HTTPS입니다.
> 로컬 IP 주소(`http://192.168.x.x`)로 접속하면 카메라가 켜지지 않습니다.

## 사용법

1. 페이지를 열고 **카메라 켜기**를 누릅니다.
2. 브라우저에서 카메라 권한을 허용합니다.
3. 기기가 지원하면 전면·후면 화면이 동시에 표시됩니다.
4. 동시 사용을 지원하지 않으면 **번갈아 전환 모드**로 자동 전환됩니다.

마이크는 요청하지 않습니다. `getUserMedia()`를 `audio: false`로 호출하므로 마이크 권한 팝업이 뜨지 않고 소리도 재생·녹음되지 않습니다.

## 녹화

카메라를 켜면 하단에 **● 녹화** 버튼이 나타납니다. 누르면 두 화면을 합쳐 **영상 파일 하나**로 저장합니다. 다시 누르면 중지되고 다운로드 폴더에 저장됩니다.

화면에 보이는 대로 녹화됩니다. 분할 방향, 순서, 표시 방식(`전체 담기`/`꽉 채우기`), 전면 반전이 모두 그대로 반영됩니다.

### 소리

`화면·줌` 패널의 **소리도 함께 녹화**가 기본으로 켜져 있습니다.

**소리는 파일에만 담기고 실시간으로는 재생되지 않습니다.** 마이크 트랙을 `MediaRecorder`에만 넣고 어떤 `<video>`나 스피커에도 연결하지 않기 때문입니다. 하울링이 발생할 경로가 없습니다.

마이크는 **녹화를 시작할 때만** 요청합니다. 카메라만 켤 때는 요청하지 않으므로, 녹화하지 않으면 마이크 권한 창이 뜨지 않습니다. 권한을 거부하면 영상만 녹화하며 실패하지 않습니다.

진단 패널의 **스피커로 나가는 소리** 항목에서 실제 상태를 확인할 수 있습니다.

### 녹화 중에는 앱이 화면에 보여야 합니다

브라우저가 백그라운드에서 카메라를 멈추기 때문에, 다른 앱으로 넘어가면 녹화를 이어갈 수 없습니다. 돌아왔을 때 카메라가 죽어 있으면 **그때까지 녹화된 내용을 저장하고** 사실대로 알립니다.

같은 이유로 **알림창(커튼)에서 녹화를 시작하거나 중지하는 기능은 만들 수 없습니다.** 알림 버튼 자체는 웹으로 만들 수 있지만, 앱이 화면에서 내려간 상태에서는 카메라가 이미 멈춰 있어 녹화할 영상이 없습니다. 눌러도 아무것도 녹화되지 않는 버튼이 됩니다.

## 홈 화면 앱으로 쓰기

주소를 입력하지 않고 아이콘 한 번으로 실행할 수 있습니다.

1. 첫 화면의 **홈 화면에 추가**를 누릅니다. (버튼이 없으면 브라우저 메뉴의 `홈 화면에 추가`)
2. **열면 바로 시작**을 체크합니다.

이후 홈 화면 아이콘을 누르면 브라우저 주소창 없이 전체화면으로 열리고, 카메라 권한이 이미 허용된 상태라면 **누르는 즉시 카메라가 켜집니다.** 네트워크가 없어도 열립니다.

`열면 바로 시작`은 권한이 이미 허용된 경우에만 동작합니다. 권한이 없는 상태에서 자동 실행하면 사용자 동작 없이 권한 창이 뜨는 셈이 되어 브라우저가 이를 차단하기 때문입니다.

### 빠른 설정 타일과 백그라운드 실행은 불가능합니다

알림창을 내려서 누르는 **빠른 설정 타일은 웹으로 만들 수 없습니다.** 타일은 [`TileService`라는 안드로이드 클래스를 앱이 제공](https://developer.android.com/develop/ui/views/quicksettings-tiles)해야 하며, 네이티브 앱만 등록할 수 있습니다.

**화면에 보이지 않는 상태로 카메라를 돌리는 것도 불가능합니다.** 크롬은 숨겨진 문서에서 카메라 시작을 막고 있으며([관련 논의](https://issues.chromium.org/issues/526039695), [안드로이드 숨은 탭 제약](https://issues.chromium.org/issues/522061496)), 서비스 워커에는 `getUserMedia`가 존재하지 않습니다. 몰래 촬영을 막기 위한 의도적 설계이므로 우회할 수 없습니다. 앱을 내리면 카메라는 반드시 멈춥니다.

## 기기 지원과 한계

전면·후면 카메라의 진짜 동시 실행은 웹 코드만으로 보장할 수 없습니다. OS와 카메라 하드웨어가 두 카메라의 동시 스트림을 지원해야 합니다.

- 안드로이드의 동시 카메라는 [Android 11부터 제공되는 선택적 기기 기능](https://source.android.com/docs/core/camera/concurrent-streaming)입니다.
- [카메라 서브시스템이 지원하지 않으면 `getConcurrentCameraIds()` 결과가 비어 있습니다](https://developer.android.com/reference/kotlin/android/hardware/camera2/CameraManager.html).
- iPhone과 iPad의 Safari는 일반적으로 활성 카메라를 한 번에 하나만 허용합니다.

실기기 확인 결과:

| 기기 | 동시 실행 |
|---|---|
| 갤럭시 탭 S7 FE | 정상 동작 |
| 갤럭시 A52s | 불가 — 한 카메라 사용 중에는 다른 카메라를 열 수 없음 |

동시 실행이 안 되는 기기를 소프트웨어만으로 가능하게 바꿀 수는 없습니다. 이 페이지는 그런 기기에서 한 번에 카메라 하나를 사용하며 약 2.2초마다 전면·후면을 전환합니다. 대기 중인 화면에는 마지막 프레임을 남깁니다.

## 기능

- 전면·후면 카메라 동시 실행 시도
- 실제 영상의 `currentTime` 진행 여부로 두 스트림이 모두 살아있는지 확인
- 동시 실행 실패 시 번갈아 전환 모드로 자동 폴백
- **두 화면을 합쳐 영상 파일 하나로 녹화** (소리 포함 선택 가능)
- **화각과 표시 방식 조절** (아래 참고)
- **기기가 지원하는 범위 안에서 줌 조절**
- 세로 화면은 위/아래, 가로 화면은 좌/우 분할
- 분할 방향 고정 및 화면 순서 변경
- 전면 카메라 좌우 반전
- 감지된 카메라 직접 선택
- 전체화면과 화면 꺼짐 방지(Wake Lock)
- 권한 거부, HTTPS 미사용, 카메라 점유 등 원인별 오류 안내
- 감지된 카메라, 실제 해상도, 줌 범위를 확인하는 진단 패널

## 화면이 확대돼 보일 때

하단 **화면·줌** 버튼에서 조절합니다. 확대돼 보이는 원인은 보통 두 가지이고, 둘 다 렌즈를 바꾸지 않고 해결됩니다.

**표시 방식** — `전체 담기`가 기본값입니다.

| 값 | 동작 |
|---|---|
| 전체 담기 | 영상을 잘라내지 않고 전부 표시합니다. 검은 여백이 생길 수 있습니다. |
| 꽉 채우기 | 화면을 빈틈없이 채우되 **가장자리를 잘라냅니다.** 그만큼 확대돼 보입니다. |

**화각** — `최대 (4:3)`이 기본값입니다.

폰과 태블릿의 카메라 센서는 4:3이 원본이고, [4:3이 센서의 전체 화각을 담는 반면 16:9는 그 일부를 잘라낸 결과](https://groups.google.com/a/android.com/g/camerax-developers/c/pbIhLO9lHjc)입니다. 따라서 넓게 보려면 4:3을 요청해야 합니다.

## 줌은 어디까지 줄어드나

**0.5배는 소프트웨어로 만들 수 없습니다.** 0.5배는 줌아웃이 아니라 초광각이라는 **별도의 물리 렌즈**로 전환하는 것입니다.

웹에서는 `applyConstraints()`로 줌을 조절하는데, 조절 가능한 범위는 기기가 직접 보고합니다. 대부분의 카메라는 최소값이 1배이며, 그보다 넓힐 방법은 없습니다. 초광각 렌즈가 별도 카메라로 노출되는 기기라면 **카메라 선택**에서 그 렌즈를 직접 고르는 것이 유일한 방법입니다.

이 페이지는 추측하지 않고 기기가 보고한 실제 범위를 그대로 보여줍니다. 진단 패널의 **후면 줌 / 전면 줌** 항목에서 현재 배율과 조절 가능 범위를 확인할 수 있고, 조절이 불가능한 카메라는 `조절 미지원`으로 표시됩니다.

> 갤럭시 탭 S7 FE는 후면 카메라가 하나뿐이므로 초광각 전환이 불가능합니다.
> 이 기기에서 화면을 더 넓히는 방법은 위의 표시 방식과 화각 설정입니다.

## 동시 실행 판정 방식

두 번째 카메라를 열 때 오류가 발생하지 않아도 첫 번째 스트림이 멈출 수 있습니다. 특히 일부 플랫폼은 첫 번째 스트림을 예외 없이 조용히 중단하므로 `try/catch`만으로 성공 여부를 판정할 수 없습니다.

이 페이지는 두 `<video>` 요소의 `currentTime`이 실제로 증가하는지 확인합니다.

```text
1. 전면 카메라 열기 → 권한 요청
2. enumerateDevices()로 카메라 목록 확인
3. 후면 카메라 열기
4. 두 영상의 currentTime 진행 여부 확인
   - 둘 다 진행: 동시 실행
   - 하나라도 멈춤: 번갈아 전환
```

## 로컬 실행

`localhost`는 HTTPS 예외이므로 로컬 개발에서 사용할 수 있습니다.

```bash
python3 -m http.server 8000
# http://localhost:8000
```

같은 와이파이의 다른 기기에서 `http://<로컬-IP>:8000`으로 접속하는 방식은 보안 컨텍스트가 아니어서 카메라가 차단됩니다. 모바일 테스트에는 GitHub Pages 링크를 사용하세요.

## 파일 구성

```text
index.html             앱 전체 — HTML·CSS·JavaScript (외부 의존성 없음)
manifest.webmanifest   홈 화면 앱 설정
sw.js                  서비스 워커 (설치 가능 + 오프라인 실행)
icon-192.png           홈 화면 아이콘
icon-512.png           홈 화면 아이콘
tools/make-icons.mjs   아이콘 생성기 (의존성 없이 node 로 실행)
README.md              사용법과 기기 제약 설명
```

아이콘을 다시 만들려면:

```bash
node tools/make-icons.mjs
```
