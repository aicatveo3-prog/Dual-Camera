# 앞뒤 카메라 (Dual Camera)

전면·후면 카메라 영상을 한 화면에 함께 보여주는 웹 페이지입니다.

**▶ [바로 열기](https://aicatveo3-prog.github.io/Dual-Camera/)**

> 카메라 API는 **HTTPS에서만** 동작합니다. 위 링크(GitHub Pages)는 HTTPS라서 그냥 열면 됩니다.
> 로컬 IP(`http://192.168.x.x`)로 접속하면 카메라가 켜지지 않습니다.

## 두 가지 방식

| 페이지 | 방식 | 되는 기기 |
|---|---|---|
| [`index.html`](index.html) | **기기 두 대를 짝지음** | 사실상 모든 기기 |
| [`solo.html`](solo.html) | 한 기기에서 두 카메라 동시 | 일부 플래그십만 |

### 왜 두 대로 나눴나

한 기기에서 전면·후면을 동시에 켜는 것은 **하드웨어가 지원해야만** 됩니다. 안드로이드에서 이것은 [Android 11부터 추가된 선택적 기기 기능](https://source.android.com/docs/core/camera/concurrent-streaming)이고, [카메라 서브시스템이 지원하지 않으면 `getConcurrentCameraIds()`가 빈 집합을 반환](https://developer.android.com/reference/kotlin/android/hardware/camera2/CameraManager.html)합니다. iOS Safari는 한 번에 활성 카메라 하나만 허용하며, 두 번째를 열면 첫 번째를 조용히 중단시킵니다.

실제로 **갤럭시 A52s(Snapdragon 778G)에서 테스트해 실패**했습니다. 삼성의 Dual recording / Director's View도 일부 플래그십에만 있어서, 네이티브 앱을 만들어도 같은 기기에서는 실패합니다. 하드웨어 제약입니다.

**기기 두 대로 나누면 이 제약이 사라집니다.** 각 기기가 카메라를 하나만 열기 때문입니다. 부수 효과로 두 카메라가 한 ISP를 다투지 않아 각자 최대 화질로 돌고, 발열도 분산됩니다.

## 페어링 방식 사용법

| 기기 | 역할 | 카메라 |
|---|---|---|
| 태블릿 등 화면 큰 기기 | **호스트** — 두 화면을 함께 표시 | 후면 (풍경) |
| 폰 | **송신** — 영상을 호스트로 보냄 | 전면 (얼굴) |

**준비 (한 번만):** [`worker/README.md`](worker/README.md)를 보고 시그널링 서버를 배포하고, 나온 주소를 두 기기에 각각 한 번 입력합니다.

**최초 1회 페어링:**

```
호스트 기기 : 페이지 열기 → "이 기기를 호스트로" → 6자리 코드가 표시됨
송신 기기   : 페이지 열기 → "이 기기를 송신용으로" → 코드 입력 → 연결
```

**그 다음부터는 두 기기 모두 페이지만 열면 자동으로 연결됩니다.** 역할과 코드를 기기에 저장해두기 때문입니다. 코드 입력도 역할 선택도 다시 하지 않습니다.

### 두 기기를 같은 와이파이에 두세요

같은 네트워크 안에서는 P2P 직결이 되어 중계 서버(TURN)가 필요 없습니다. 지연도 보통 50~150ms로 보기에 무리 없습니다.

다른 네트워크(한쪽은 와이파이, 한쪽은 LTE)라면 NAT 종류에 따라 직결이 실패할 수 있고, 그때는 TURN 중계 서버가 필요합니다. 무료로 구하기 어렵고 트래픽 비용이 발생하므로 권하지 않습니다.

## 소리는 전송하지 않습니다

통화처럼 소리가 들리는 일은 없습니다. 세 겹으로 막혀 있습니다.

1. `getUserMedia`에 `audio: false`를 넘깁니다 — **마이크 권한 팝업조차 뜨지 않습니다**
2. 비디오 트랙만 `addTrack`합니다 — 전송 트랙에 오디오가 없습니다
3. 모든 `<video>`에 `muted`를 강제합니다 — 스피커로 나갈 경로가 없습니다

진단 패널의 **오디오 트랙** 항목에서 로컬·원격 모두 `0개`임을 직접 확인할 수 있습니다.

나중에 녹화 기능을 붙일 때도 소리가 나게 만들 필요가 없습니다. 송신 기기에서 마이크를 잡아 트랙으로 보내되 호스트에서 그 트랙을 스피커에 연결하지 않고 `MediaRecorder`에만 넣으면, **녹화 파일에는 소리가 담기지만 실시간으로는 아무 소리도 나지 않습니다.** 하울링도 원천적으로 없습니다.

## 기능

- 화면 방향에 따라 분할 방향 자동 전환 (세로 위/아래, 가로 좌/우)
- 분할 방향 고정, 두 화면 순서 바꾸기, 상대 화면 좌우 반전, 전체화면
- 화면 꺼짐 방지 (Wake Lock)
- 연결이 끊기면 지수 백오프로 자동 재접속
- 진단 패널 — 연결 상태, ICE 상태, 해상도, 오디오 트랙 수 확인

## 구성

```
index.html   기기 페어링 방식 (기본)
app.js       페어링·WebRTC·카메라 로직
app.css      스타일
solo.html    한 기기에서 두 카메라 동시 (단일 파일, 의존성 없음)

worker/
  src/index.js        시그널링 서버 (Worker + Durable Object)
  wrangler.toml       배포 설정
  test/room.test.mjs  중개 로직 테스트 (의존성 없이 node로 실행)
  README.md           배포 방법과 프로토콜
```

외부 CDN이나 프레임워크를 쓰지 않습니다. 빌드 단계도 없습니다.

## 테스트

```bash
node worker/test/room.test.mjs
```
